## 三·补、strings 归零的深水区处置

图纸删30+清14是旧树坐标；现树 strings 四计数还受三处新增面影响，均已纳入 B2 处置：

1. **i18n 字符串表**（主）：`english.yaml` 23 个摘抄/书签键 → 删键 + 重新生成 I18n 三文件。保留项 UI 标签（`STR_BOOKMARK_OPTION`/`STR_SAVE_CLIPPING` 等）先降级为 `STR_IGNORE`，故这些 StrId 在源码零引用后才删键。
2. **KOReader `syncClippings` JSON 键**（图纸保留项）：`"syncClippings"` 字面量含 Clippings，会命中 strings。按图纸"读时忽略、写时不再产生"——删 `KOReaderCredentialStore.cpp` 的 toJson/fromJson 两处字面量读写（写不再产生；读时 JSON 缺匹配键自然忽略），getter/setter 标识符保留不进 strings。删 `SettingsList.cpp` 的 `"koSyncClippings"` 设置项 emit。`BleSettingsActivity`/`KOReaderSettingsActivity` 的相关 label 降级 STR_IGNORE。
3. **文件移动**：`ClippingStore::moveBook` 兼做书籍文件移动（`Storage.rename`），被 FileBrowser/WebServer/WebDAV 调用——不能连功能一起删。改为直接 `Storage.rename`，保留书籍重命名/移动，仅去掉摘抄目录迁移。
